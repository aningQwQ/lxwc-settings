# lxwc-settings 开发守则

本守则适用于 `lxwc-settings` 的所有代码、测试、文档和发布流程。

核心原则：

> **modules 管意图，适配器管解释，services 管执行，app 管协调。**

## 1. 分层与依赖方向

```text
core        领域模型，不依赖 UI 和外部系统
services    通用能力：文件、进程、worker
wlr         WLR / wlr-randr 适配器
labwc       rc.xml、environment、autostart、XKB、快捷键适配器
plugins     无 UI 预设
modules     页面状态和 UI，不碰文件、不碰子进程
app         模块路由、任务聚合、跨模块请求
ui          纯控件和样式
```

必须遵守：

- `modules` 可以依赖适配器，但不能依赖 `services::fs` 或 `services::process`。
- `wlr` 与 `labwc` 之间不能互相 import。
- 适配器不能依赖 `modules` 或 `ui`。
- `core` 不能依赖任何外部系统适配器。
- `app` 负责跨模块路由，模块之间不要直接调用彼此的实现。
- 持久化统一通过 `Effect::WriteFile` 和 `Effect::RunCommand` 完成。

## 2. 文件规则

- 文件路径、文件格式、解析、补丁、标记块，归对应适配器。
- 物理读取、备份、原子替换，归 `services::fs`。
- 模块不能出现 `std::fs`、`services::fs`、`read_to_string` 等直接文件访问。
- 模块需要文件内容时，调用适配器的 `load()`。
- 模块需要写入时，生成 `Effect::WriteFile`，交给 app 和 worker。

持久化写入必须带期望快照：

```rust
Effect::WriteFile {
    path,
    contents,
    expected,
}
```

`expected` 用于检测外部修改，不能绕过。

## 3. 命令规则

- `Command::new` 只能出现在 `services::process`。
- 子进程执行统一走 `services::process::run`。
- 命令参数拼装归对应适配器：
  - `wlr-randr` 命令归 `wlr`
  - `labwc --reconfigure` 归 `labwc::reconfigure`
- 模块不能手写 `wlr-randr --output ...` 这类命令字符串。
- 实时显示切换属于 WLR 适配器的异步 worker，不走 `Effect::WriteFile`。
- 持久化相关命令走 `Effect::RunCommand` 或 `services::process`。

## 4. 专有逻辑归属

- XML 解析、XPath、keybind、action 语法：`labwc/rc_xml.rs`
- environment 文件格式：`labwc/environment.rs`
- autostart 标记块：`labwc/autostart.rs`
- XKB 布局解析与合并：`labwc/layouts.rs`
- 快捷键组合键编辑语法：`labwc/keycombo.rs`
- WLR 输出解析、模式命令：`wlr/`

判断标准：

> 如果一段逻辑只对某个外部系统有意义，它就不能留在 `modules`。

## 5. 模块规则

模块只允许拥有：

- 页面控件和布局
- 用户选择状态
- 编辑中的草稿
- 待执行变更
- 错误和状态提示
- `is_valid()` 之类的输入校验

模块不允许：

- 直接读写文件
- 直接启动进程
- 直接解析 XML
- 直接拼外部命令
- 直接操作其他模块

UI 约定：

- 页面过长必须使用 `ScrollArea`。
- 不添加无意义外框，优先使用 `ui.scope`、`ui.separator` 和分节标题。
- 状态使用明确的成功、警告、错误颜色。
- 清除、禁用、空状态必须有明确反馈。
- 无效输入必须通过 `is_valid()` 阻止 Apply，而不是只显示提示。

## 6. 国际化规则

- 用户可见文本只能通过 `t("key")` 或 `trf!("key", args)`。
- 不能在代码中硬编码中文或英文界面文本。
- 新键必须同时加入：
  - `locales/en-US.lang`
  - `locales/zh-CN.lang`
- 删除功能时同步删除无用翻译键。
- README 以英文为主，中文内容放在 `README.zh-CN.md`。

## 7. Rust 与代码风格

- 使用 Rust 2021 和 egui/eframe 0.28。
- 默认不写注释，除非确实需要解释非显而易见的约束。
- 错误信息尽量使用翻译键。
- 优先返回 typed state，避免让模块反复拼字符串。
- 不引入未使用的抽象层。
- 新增逻辑优先放入已有适配器或 services，不随意新增顶层模块。

## 8. 测试规则

必须覆盖：

- 适配器：解析、补丁、标记块、命令拼装。
- services：原子写入、备份、外部修改检测。
- 模块：状态切换、pending 任务、清空后无残留任务。
- 跨模块：多个模块修改同一文件时只生成一个写入任务。

提交前执行：

```bash
cargo fmt --check
cargo build --offline
cargo test --offline
cargo build --release --offline
```

真实配置校验：

```bash
LXWC_TEST_RC="$HOME/.config/labwc/rc.xml" cargo test real_config
```

## 9. Git 与发布规则

- 未经明确要求不要 commit。
- 提交信息使用现有风格：
  - `feat:`
  - `fix:`
  - `refactor:`
  - `docs:`
  - `release:`
- 发布流程：
  - 更新 `Cargo.toml` 和 `Cargo.lock`
  - 构建 x86_64 release
  - 打包 `lxwc-settings-X.Y.Z-x86_64-linux.tar.gz`
  - 包内包含二进制、`LICENSE`、`README.md`、`README.zh-CN.md`
  - 打 tag `vX.Y.Z`
  - 推送并创建 GitHub Release

## 10. 允许的例外

以下情况目前允许，但要谨慎：

- `labwc/themes.rs`、`labwc/layouts.rs` 直接扫描系统目录或读取 `evdev.lst`，因为路径和格式属于适配器知识。
- `main.rs` 启动时读取字体文件，属于应用启动逻辑，不在模块层。
- `modules` 中可以出现 XPath 字符串和环境变量键名，因为它们描述“改哪个配置项”，但文件格式处理仍归适配器。
- `modules/labwc_display` 可以维护当前选择、持久化模式和配置快照状态，但不应重新实现 autostart 格式。

## 11. 提交前检查清单

- [ ] 模块没有直接访问文件或启动进程。
- [ ] 适配器没有依赖 `modules` 或 `ui`。
- [ ] 新增文本已加入中英文翻译。
- [ ] 新增解析、补丁或状态逻辑有测试。
- [ ] 页面可滚动，空状态和错误状态清晰。
- [ ] `cargo fmt --check` 通过。
- [ ] `cargo test --offline` 通过。
- [ ] `cargo build --release --offline` 通过。
